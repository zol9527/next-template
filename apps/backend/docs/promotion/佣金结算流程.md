# 佣金结算流程详解

本文档说明分销系统中佣金的状态流转机制，确保推广员收益的准确性和平台资金安全。

## 佣金状态定义

佣金在其生命周期内经历以下状态流转：

| 状态 | 说明 | 金额统计 |
|------|------|----------|
| `frozen` | 冻结中 - 订单已支付但未完成 | 计入 frozenCommission |
| `payable` | 可提现 - 订单已完成，可申请提现 | 计入 payableCommission |
| `settled` | 已结算 - 佣金已发放 | 计入 settledCommission |

## 各状态详细说明

### 1. frozen（冻结中）

**触发条件**：订单支付成功

**设计目的**：
- 风险控制：防止订单退款时佣金已被提走
- 审核窗口：给予平台审核订单的时间
- 退款保障：用户退款期内冻结佣金

**限制**：
- 不能参与结算
- 不能提现
- 订单退款时可自动调整金额或标记为 voided

### 2. payable（可提现）

**触发条件**：
- 订单完成且超过退款期
- 课程/服务已成功交付
- 管理员手动解冻

**设计目的**：
- 确认订单无退款风险
- 推广员可以申请提现
- 佣金进入可执行状态

**权限**：
- 可参与结算
- 可申请提现
- 计入可提现总额

### 3. settled（已结算）

**触发条件**：
- 管理员审核通过并发放佣金
- 系统自动结算周期执行
- 推广员提现成功

**设计目的**：
- 佣金已实际到账
- 完成整个收益闭环
- 计入已结算总额

## 统计口径

推广员首页/后台统计的佣金数据按以下规则计算：

```typescript
// 累计佣金 = frozen + payable + settled
totalCommission = frozenCommission + payableCommission + settledCommission

// 可提现金额 = payable
payableAmount = payableCommission

// 冻结中金额 = frozen
frozenAmount = frozenCommission

// 已结算金额 = settled
settledAmount = settledCommission
```

## 完整订单流程

```
用户下单 → 支付成功 → 创建佣金(frozen) → 等待完成 → 解冻(payable) → 申请提现 → 结算(settled)
                              ↓                    ↓
                          退款处理            管理员审核
                              ↓
                          调整/作废佣金
```

## 风控意义

1. **保护平台**：避免大量退款时平台资金链断裂
2. **保护推广员**：确保佣金结算基于真实完成的订单
3. **透明可查**：推广员可实时查看各状态佣金金额
4. **标准实践**：主流分销平台（如淘宝客、拼多多）均采用类似机制

## 常见问题

**Q: 订单完成后多久佣金变成可提现？**

A: 这取决于业务配置。通常课程类商品在课程交付后立即可提现，实物商品在收货/过退货期后解冻。

**Q: 冻结期间的佣金会产生收益吗？**

A: 冻结期间佣金仅是状态标识，不产生额外收益，解冻后按实际金额结算。

**Q: 如何查看我的冻结佣金对应的订单？**

A: 推广员可通过佣金记录列表查看每笔佣金的订单来源和当前状态。
